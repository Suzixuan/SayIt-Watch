## 1. 用户问题与已确认事实

用户复现：先开手表，后开电脑，设置里的连接/切换无效，必须退出重开；当前电脑 IP 没有明确出现；“以下电脑都已验证通过”又长且不符合状态；台式机和笔记本不能依赖不同的软件包。

PM 静态确认：

1. 台式机旧启动器依赖固定源码目录的 Vite 服务，笔记本包依赖 Node 和另一个前端服务。相同 EXE 哈希不能证明交付一致。
2. `RecordingScreen` 的 `LaunchedEffect(ui.screen)` 仅在页面变化时触发 Ready 搜索，首次失败后缺少前台恢复调度。
3. `ResolverEngine.onReadyEntered(force=true)` 在 Automatic 模式返回 NoOp；`handleSwitchBrowse` 的早退路径调用 `endPickerSearch`，会取消当前 Automatic，未确保用户点击产生新一轮。这是可复现候选根因，不应宣称已证明用户现场全部故障。
4. `publishTargets()` 从 rememberedTargets 建列表，当前目标单独维护；切换页只遍历列表。顶部说明始终显示“以下电脑都已验证通过”，没有根据搜索/空列表状态区分。
5. `openConfig()` 会清空 verifiedDestination；`requestSwitch()` 目前可能自动选择唯一新候选。本轮新契约分别要求查看设置不丢目标、显式切换必须点选。

先用生产路径回归测试复现以上边界，再进行最小修改，不能继续仅测纯文案函数或源代码字符串。

## 2. 冻结行为契约

### A. 搜索任务与前台恢复

- 启动、返回前台、重新搜索、显式切换统一由一个任务所有者调度。任务有 generation；取消完成后才启动替代任务，晚到结果不得改 UI、当前目标或持久化设置。
- 同时最多一轮搜索/认证；连续点击合并为最近一次意图，不丢最后一次请求、不累积协程/NSD listener/worker。
- 有效 Token、应用前台、Ready 未连接、且无录音/上传/配置编辑/选择器占用时，立即搜索；失败后等 5 秒重试。保留每轮旧地址 3 秒、浏览 8 秒的预算。退后台、进入录音/上传或销毁时取消调度与浏览，不能后台常驻轮询。
- 返回前台立即重新验证保存的/上次目标；正在重新验证期间显示“正在连接…”，不能把历史认证当作当前在线证据。前台 Ready 已连接且空闲时每 5 秒执行一次有界认证探针（沿用 3 秒预算），失败即清除当前可用状态并进入恢复；禁止与浏览/手动认证重叠。录音/上传期间不抢占既有一次性传输链路。
- “重新搜索”在搜索中仍可表达重启意图，完成旧任务取消后立即开始最新请求。不能因为旧 Automatic/NSD 正在运行而静默返回。
- 自动恢复时，旧目标本轮重新认证成功则保留；无有效旧目标时，仅一个候选自动连接，多候选显示选择器并暂停自动挑选。已连接时不因发现另一台而跳转。
- 显式切换始终显示候选让用户点选，包括只有一个新候选。取消保留仍在线的当前目标；目标已确认离线则不能伪装保留连接。选中历史候选前重新认证，失败不写设置。
- 未认证目标不可录音/上传；任何恢复不会重发已结束的音频。保留现有一次 WAV/一次上传语义。

### B. 页面与设置

- Ready 表盘、麦克风、已批准设置菜单入口、光学居中保留；只改连接状态文案和设置内切换页，不再往 Ready 加大按钮。
- 切换页顶部独立显示“当前电脑”及真实当前 `IP:端口`，即使当前目标不在发现列表也必须显示；无有效当前目标显示“未连接”。旧保存地址只能明确标为“上次使用”，不可标当前连接。
- 列表仅用“当前使用”“可选电脑”等短标识；搜索中“正在搜索…”，结束无候选“未找到电脑”，操作“重新搜索”“返回”。删除固定的长“验证通过”说明。
- 打开设置、查看连接配置、取消选择不清除当前目标、不重写 Token。配置页返回也保留未改配置的目标；只有实际提交了连接配置变化才作相应失效和验证。输入表单的临时内容不等于已保存配置。
- 当前状态/候选/搜索任务由一致状态源投影到 UI，不在 UI 伪造“已连接”。诊断仍为固定类别，不输出 Token 或识别文字。
- 视觉从 `design/watch-ui/0.3.0-dev.1-candidate.4/` 继承，新增 `design/watch-ui/0.3.0-dev.2-candidate.1/` 保存修改前态、480×480 圆屏预览、修改说明与 SHA-256。旧候选不可覆盖。新切换页作为待 PM 视觉验收候选，不擅自部署。

### C. 一个 Windows 便携包

- 产物名 `SayIt-Watch-0.3.0-dev.2-windows-x64-portable.zip`；两台 Windows 电脑使用相同 ZIP、同一入口 `SayIt.exe`。可提供同义快捷启动脚本，但不能因电脑角色分包。

## 4. 必须覆盖的验收场景

| 场景 | 输入/操作 | 预期与失败条件 |
|---|---|---|
| A 晚启动 | 手表前台等待首轮失败，再启动电脑 | 下一轮搜索连接，不退出重开；没有第二次搜索或需手动 IP 即失败 |
| B 抢占与取消 | 初始搜索中进入切换，连点重新搜索，返回再进入 | 最后意图生效，单任务，旧结果不回流；永久转圈/按钮假成功/叠加 worker 即失败 |
| C 两台与显式选择 | 同 Token 两台在线，一台已连接，进入切换 | 当前 IP 始终可见，点另一台才切换，取消不改当前；唯一候选自动切换也算失败 |
| D 重连 | 电脑关闭/重开、地址改变、手表后台再前台 | 有界失效与恢复；离线目标一直显示已连接即失败；录音/上传不被后台探针抢占 |
| E 设置查看 | 已连接→配置页→未编辑返回；再提交实际变化 | 查看不丢目标/不写配置；实际变化才验证；旧保存地址不能冒充在线 |
| F 真实用途 | 台式机→笔记本及反向切换，各录一句 | 文字只进入选定电脑输入框；不重复上传，不向原电脑误发 |
| G 统一包 | 同一个 ZIP 解压在两台电脑、含空格/中文路径，无 Node/源码服务 | 应用独立启动、发现与录音闭环；借开发服务器显示 UI 即失败 |
| H 启动失败 | 隔离临时配置缺失、受控测试端口占用 | 可见可理解提示、无敏感值，原配置不变，不杀进程；仅日志报错即失败 |

先跑定向回归（真实 ViewModel→Resolver→fake discovery/probe→UI 投影，虚拟时钟验证 5 秒间隔/前后台取消），再 `gradlew.bat testDebugUnitTest --rerun-tasks lintDebug assembleDebug`。Windows 运行受影响 Rust 定向测试、前端 build、统一包构建和独立目录启动冒烟；如改前端业务，补受影响测试。保留 Release 接收端隔离证据，新增打包不能破坏原边界。无需为了数字重复不相关全量测试。

无真实设备时明确 A–G 的设备部分未验证，不拿 fake 单测/构建/401 代替端到端验收。D 不自行连接/安装手表，不停止用户正在运行的程序。受控启动冒烟使用隔离环境和测试配置，凭证保持本地且不写入交付证据。
