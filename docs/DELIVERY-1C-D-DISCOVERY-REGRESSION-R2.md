# Delivery 1C 自动发现与换电脑：1C-D-04@R2

状态：待派发。上一版本 `1C-D-04@R1` 未派发；本版增加笔记本同症状及“不再每次手动改 IP”的用户验收目标。继承 R1 的已验证基线、诊断纪律和禁止事项；本文件是本轮唯一有效要求，冲突时以本文件为准。

## 目标与证据

用户在台式机、笔记本均遇到自动发现失败，但手动填写对应局域网 IPv4 后能连接。2026-09-19 台式机运行最新已验收 Debug EXE，接收端 `0.0.0.0:18099` 正常，发现接口无 Bearer 返回预期 401，日志出现真实 mDNS `Announce`。该日志只证明本机发出广播，不能证明手表收到。台式机失败时未观察到可归因于 Watch 的认证探针；手表 ADB 当前无在线设备，未取得本轮 found/resolve 回调。此前笔记本曾报告 mDNS 已恢复，但手表重启复用了保存的笔记本地址，没有完成新鲜发现验收；不得把笔记本根因当作已确定。

当前只能把失效边界定位在 Watch NSD 收取/解析、候选过滤或认证探针前后。`AndroidNsdDiscovery.kt` 的成功回调不可观测，`serviceInfo.host?.hostAddress` 只取一个地址、类型严格比较，以及已保存地址优先，均是待验证假设，不是已证实的根因。`asrReady=false` 是独立 ASR 问题，本轮不碰。

用户目标是：在同一 Wi-Fi 上从台式机换到笔记本或反向换回时，正常使用不必清手表数据、重输 Token 或手打 IP。为保证不把音频发错电脑，两个同 Token 电脑同时可用时只能由用户明确选择已认证目标。

## 冻结行为与验收

1. 只运行一台电脑、保存地址已失效：最多 3 秒旧地址复查后，最多 8 秒浏览并认证当前电脑，保存新目标进入 Ready；手表无需手动改 IP。台式机→笔记本和笔记本→台式机各测一次。
2. 旧电脑仍在线时保留“旧地址认证成功就继续使用”行为；提供显式“切换电脑”入口，触发新的浏览并允许选择另一台已认证电脑。两个认证目标并存时不得按发现顺序或仅凭相同 Token 静默切换。选择界面可显示局域网地址用于区分，但不得在广播、日志或外部回传中显示地址；不需要输入地址。
3. 发现结果、手动输入或用户选中的目标，都必须经过现有 Bearer 探针且服务标识/协议匹配后才能成为上传目标；未认证服务不可选。0 个认证目标进入有界手动兜底；不得形成常驻扫描、listener 泄漏或每次进 Ready 反复弹选择。
4. 既有录音→WAV→上传→ASR→Paste 路径、requestId、一个录音最多上传一次、Release HTTP 隔离保持原样。PM 真机复测前不得宣称自动切换 VERIFIED；构建和 fake 测试不代替真机。

## D 的工作范围

D 为本轮唯一产品源码写入者。先用最小、限量且不含敏感值的阶段诊断，把旧地址探针、浏览启动/失败、found、resolve 成功/失败、候选拒绝固定类别、认证探针结果类别及最终兜底区分开。不得输出 Token、IP、主机名、原始 exception message、HTTP 请求或音频。先给 PM 报告定位证据与修正假设；只对证据支持的原因做最小修复。若本轮仍无手表日志，只能交付诊断候选，不能猜根因或宣称修好。

允许改：`watch/app/src/main/java/com/sayit/watch/net/AndroidNsdDiscovery.kt`、`Discovery.kt`、`DiscoveryCoordinator.kt`、`ui/RecordingViewModel.kt`、`ui/RecordingScreen.kt`、必要的 `settings/**`、对应 `watch/app/src/test/**` 和字符串资源。UI 仅限明确切换和已认证目标选择；不能扩到录音、传输、Windows receiver、Provider/ASR、History、Paste、依赖、权限或发布代码。若确实需要上述范围外路径，先报 PM 审核，不自行扩围。

保留标准 DNS-SD/mDNS 服务类型和 TXT、Debug-only、RFC1918 IPv4、常量时间 Bearer、3 秒旧址/8 秒浏览上限。除“用户显式选择两个已认证电脑”外，延续现有 0/1/多个候选策略；后台发现仍不能静默选多个匹配目标。不得清手表应用数据、改 Token、防火墙/网络类别、正在使用的桌面程序；不得安装 APK、reset/clean/覆盖未跟踪文件、push/merge/tag/release。
